# 总览与设计原则

状态：最终技术设计版本，可持续迭代  
更新时间：2026-05-28

## 系统目标

本系统不是普通聊天机器人，而是一个可调用工具、可接入外部工具协议、可管理知识库、可运行子 Agent、可处理文件和图谱知识，并且具备安全拦截、审批、日志、错误恢复能力的 Agent 系统。

核心能力：

- 与用户进行多轮对话，并支持文字流式输出。
- 支持文件上传、解析、切 chunk、embedding、入库和检索。
- 使用 Milvus 做主向量检索。
- 使用 Neo4j 做实体关系、多跳路径和 GraphRAG。
- 使用 MinIO 保存原始文件、解析结果、chunk、日志、运行产物和加密后的 Secret 对象。
- 使用 LangChain 定义模型连接、工具和基础 Agent 能力。
- 使用 LangGraph 编排工作流、工具调用、校验、审批、重试和恢复。
- 支持内置 Tool、MCP Tool、Skill、SubAgent。
- 支持受控联网、沙盒执行、审批流和统一 ToolResult。

## 设计边界

- 不设置独立转发层，统一由 Agent Server / Agent Runtime 承担入口、编排和治理职责。
- 后端主线为 Python + LangChain + LangGraph。
- 数据层限定为 MinIO + Milvus + Neo4j。
- 不引入 pgsql、PostgreSQL、MySQL 或独立 Catalog 数据库；session、run、job、document、chunk、memory 索引关系使用 MinIO 显式索引对象保存。
- Redis 仅作为可重建缓存，不作为主状态存储，也不作为锁或队列。
- P0 使用 MinIO Secret Store 保存加密密钥；主密钥由部署环境变量 `AGENT_MASTER_KEY` 提供，前端、模型、日志、ToolResult 都不能返回明文密钥。
- 所有外部能力进入系统后都必须被 Runtime 治理，不能让模型直接绕过权限、审批、日志和错误协议。
- 所有 P0 技术设计必须写到可开发粒度，关键接口需要包含请求/返回结构、执行流程或伪代码。
- 涉及模型工具时，伪代码优先使用 LangChain `@tool` / `StructuredTool` / Pydantic args schema 表达；涉及 Agent 编排时，伪代码优先使用 LangGraph `StateGraph`、节点和条件边表达；底层 Connector、对象存储、数据库驱动和索引重建可以使用普通 Python 服务接口表达。
- 已确认问题记录在冲突与决策文档中，后续新增争议点继续追加并逐个解决。

## 术语定义

| 术语 | 定义 |
| --- | --- |
| Tool | 系统可执行能力，可以是内置工具、数据库工具、网络工具、文件工具或 MCP Tool |
| MCP | 外部工具协议，负责把外部服务的 tools / resources / prompts 暴露给 Runtime |
| Skill | 提示词、流程、知识包、操作经验和可选脚本的组合；脚本必须通过 Runtime 受控执行 |
| SubAgent | 带角色、目标、工具集合、预算和上下文边界的执行单元 |
| User | 使用系统的人；P0 默认 `default_user`，但所有数据结构保留 `user_id` |
| Role | 用户权限角色；P0 默认 `owner`，但结构保留 owner / admin / editor / viewer 扩展 |
| Workspace | 项目空间，不是对话窗口；隔离知识库、thread、run、配置、日志和项目记忆；P0 默认只有 `default` |
| Thread | 前端可见的一个对话窗口，历史会话列表中的一条记录 |
| Run | Thread 中一次用户提交后触发的一次 Agent 执行 |
| Job | 后台长耗时工作单，例如文档入库、embedding 重建、图谱构建、日志归档、诊断包和 MCP capability refresh；与 Run 分开 |
| Message | Thread 消息流中的一条用户或 assistant 持久化消息 |
| Agent Runtime | 工具治理、安全策略、审批、日志、事件、ToolResult 和运行边界 |
| Agent Server | 对外 API、会话管理、Run / Job 管理、事件推送和 Runtime 调度入口 |
