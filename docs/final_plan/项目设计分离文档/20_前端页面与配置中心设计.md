## 前端目标

前端不是简单聊天框，而是 Agent 系统的操作台。它需要同时支撑：

- 主对话。
- 工具状态可视化。
- 审批交互。
- 知识库管理。
- 模型 API 配置。
- 数据库连接配置。
- MCP 配置。
- Skill 管理。
- 记忆管理。
- 后台任务中心。
- 日志和运行追踪。

### SSE 客户端封装

P0 使用 `fetch + ReadableStream`，不使用 `EventSource`。

原因：

- 需要携带 Authorization header。
- 需要主动传 `after_event_id`。
- 切换 thread 时需要明确 abort 当前流。
- 需要统一处理 HTTP 错误、鉴权失败、重连退避和用户取消。
- 需要把 SSE 事件写入 `runStore.last_event_id_by_run` 做断线补偿。

封装接口建议：

```ts
type RunEventStreamOptions = {
  workspaceId: string
  runId: string
  afterEventId?: string
  signal: AbortSignal
  onEvent: (event: RunEvent) => void
  onError: (error: StreamError) => void
  onClosed: () => void
}

type JobEventStreamOptions = {
  workspaceId: string
  jobId: string
  afterEventId?: string
  signal: AbortSignal
  onEvent: (event: JobEvent) => void
  onError: (error: StreamError) => void
  onClosed: () => void
}

function connectRunEventStream(options: RunEventStreamOptions): Promise<void>
function connectJobEventStream(options: JobEventStreamOptions): Promise<void>
```

### 主对话页布局

P0 使用三栏布局，窄屏时右侧详情抽屉化：

```text
左侧：会话列表 / 搜索 / 新建对话
中间：当前 thread 的消息流 / 输入框 / 流式输出
右侧：当前 run 的工具、引用、审批、日志摘要
```

左侧会话列表：

- 顶部固定“新建对话”按钮。
- 搜索框按标题和最近消息摘要过滤。
- 列表项显示 title、last_message_preview、last_message_at、current_run_status。
- running / waiting_approval / failed 状态需要有明显状态标识。
- 支持置顶。
- 支持重命名。
- 支持归档。
- 支持软删除，默认不物理删除。
- 默认展示 active thread；归档和回收站用筛选入口查看。
- 点击 thread 时切换中间消息流，不删除当前 thread 的历史。

中间消息流：

- 首次打开 thread 时请求 `GET /workspaces/{workspace_id}/threads/{thread_id}` 和 `GET /workspaces/{workspace_id}/threads/{thread_id}/messages?limit=50`。
- 向上滚动时用 `before_message_id` 分页加载更早消息。
- 新建 thread 后消息流为空，等待用户输入。
- 用户提交消息时调用 `POST /workspaces/{workspace_id}/threads/{thread_id}/runs`，拿到 `run_id` 后连接 `/workspaces/{workspace_id}/runs/{run_id}/events/stream`。
- assistant 流式输出先根据 SSE 渲染临时内容，收到最终 `assistant_message` 后替换为持久化消息。
- 如果切换到旧 thread 且当前 run 已结束，只展示历史消息，不保持 SSE。
- 如果切换到旧 thread 且 current run 仍在运行，读取 `last_event_id` 后恢复 SSE。

右侧运行详情：

- 当前 run 状态。
- Tool 调用列表。
- Tool 参数摘要。
- ToolResult 摘要。
- GraphRAG 引用来源。
- 审批卡片。
- 错误和重试摘要。
- 跳转日志审计页的 run_id 链接。

GraphRAG 结果展示 P0 只做路径和证据列表，不做完整节点关系画布：

```text
实体候选列表
关系路径列表
路径方向、关系类型、强弱标记
证据卡片
来源文档 / 页码 / chunk_id
跳转文档详情
```

GraphRAG 路径展示示例：

```text
林黛玉
  -> PARTICIPATED_IN
海棠诗社结社
  <- PARTICIPATED_IN
贾宝玉

证据：
- example.pdf 第 12 页，chunk_001
- relation_strength: strong
- direction_preserved: true
```

P1 再考虑完整图谱画布，例如节点拖拽、缩放、点击展开、多跳可视化和布局性能优化。

主对话状态数据：

```json
{
  "active_thread_id": "thread_001",
  "active_run_id": "run_004",
  "last_event_id_by_run": {
    "run_004": "evt_run_004_000000000088"
  },
  "message_pagination": {
    "before_message_id": "msg_thread_001_000000000001"
  }
}
```

前端状态规则：

- `active_thread_id` 决定中间消息流。
- `active_run_id` 决定当前 SSE 订阅。
- 切换 thread 时要用 `AbortController` 关闭旧 fetch stream。
- 旧 thread 的消息不进入新 thread 的输入上下文。
- 左侧列表通过 `GET /workspaces/{workspace_id}/threads` 定期或在事件后刷新摘要。
- 刷新浏览器后，根据 URL 中的 `thread_id` 恢复当前 thread；没有 `thread_id` 时默认打开最近 active thread，或者创建新 thread。

### 会话操作交互

新建对话：

```text
点击新建对话
  -> POST /workspaces/{workspace_id}/threads
  -> URL 切换到 /chat/{thread_id}
  -> 中间显示空消息流
  -> 输入第一条消息后 POST /workspaces/{workspace_id}/threads/{thread_id}/runs
```

打开旧对话：

```text
点击左侧 thread
  -> 关闭当前 SSE
  -> GET /workspaces/{workspace_id}/threads/{thread_id}
  -> GET /workspaces/{workspace_id}/threads/{thread_id}/messages?limit=50
  -> 如果 current_run_status 是 running / waiting_approval / recovering
       连接 GET /workspaces/{workspace_id}/runs/{run_id}/events/stream
     否则只展示历史
```

删除对话：

```text
点击删除
  -> 二次确认
  -> DELETE /workspaces/{workspace_id}/threads/{thread_id}
  -> thread 进入 soft_deleted
  -> 默认列表隐藏
  -> 原 messages / runs / events 保留
```

归档对话：

```text
点击归档
  -> PATCH /workspaces/{workspace_id}/threads/{thread_id} status=archived
  -> 默认列表隐藏
  -> 归档筛选可见
```

API 页面需要显示 token 预算说明：

```text
可用输入预算 = context_window_tokens - max_output_tokens
Hermes 压缩触发点 = context_window_tokens * 0.50
session hygiene 二级保护 = context_window_tokens * 0.85
context overflow = prompt_tokens + max_output_tokens > context_window_tokens
```

context overflow 提示文案：

```text
当上下文超出模型窗口时，系统会自动执行 Hermes 压缩并最多重试一次。仍失败时，请减少输入内容、缩小检索证据范围，或调大 context_window_tokens。
```

保存模型配置流程：

```tsx
async function submitModelConfig(values: ModelConfigFormValues) {
  let apiKeyRef = values.api_key_ref;

  if (values.new_api_key_plaintext) {
    const secret = await agentApi.createSecret({
      type: 'model_api_key',
      display_name: `${values.model} API Key`,
      plaintext: values.new_api_key_plaintext,
      scope: 'workspace',
    });
    apiKeyRef = secret.secret_ref;
  }

  await agentApi.updateModelConfig('main_chat', {
    provider: values.provider,
    base_url: values.base_url,
    api_key_ref: apiKeyRef,
    model: values.model,
    context_window_tokens: values.context_window_tokens,
    max_output_tokens: values.max_output_tokens,
    timeout_ms: values.timeout_ms,
  });
}
```

- use_ssl。

- list collections。

- uri。
- credential_ref。
- database。
- readonly user flag。
- TLS 配置。

```ts
async function openJob(jobId: string) {
  const workspaceId = useIdentityStore.getState().workspaceId;
  const lastEventId = useJobStore.getState().lastEventIdByJob[jobId];
  const abortController = new AbortController();

  await connectJobEventStream({
    workspaceId,
    jobId,
    afterEventId: lastEventId,
    signal: abortController.signal,
    onEvent: useJobStore.getState().applyJobEvent,
    onError: (error) => useJobStore.getState().markStreamError(jobId, error),
    onClosed: () => useJobStore.getState().markStreamClosed(jobId),
  });
}
```

## UI 设计原则

- 配置页使用分组和标签页，不做一个超长表单。
- 密钥字段默认隐藏；已保存密钥只显示 masked，不回显明文；清空表示解除引用，不直接删除 Secret。
- 连接测试要显示具体失败分类。
- 高风险操作用审批弹窗，不把用户带离当前流程。
- Tool 运行状态必须可追踪，但不要让原始 JSON 淹没主对话。
- 对数据库和模型配置错误，给出可执行的修复提示。
