## 定位

现有日志体系主要覆盖：

- 单次 Agent run 的事件流。
- ToolResult。
- 审批。
- operations / rollback。
- MCP stderr / Skill stdout stderr 的部分产物。

这些必须保留，但它们不等于完整系统运行日志。完整排障还需要记录 Agent Server、Agent Runtime、配置加载、网络连接、数据库连接、MCP 进程、模型 Provider、SSE 连接、后台任务、缓存、SecretResolver、IndexRebuilder 等底层组件运行状态。

P0 日志体系分为五层：

| 层级 | 作用 | 是否模型可见 |
| --- | --- | --- |
| Agent Run Event Log | 当前 run 的业务事件、SSE 补发、审计回放 | 只通过受控 safe log tool 返回摘要 |
| Operation / Audit Log | 副作用、审批、回滚、配置变更审计 | 只返回脱敏摘要 |
| System Runtime Log | 系统进程级运行、异常、组件生命周期、后台任务 | 不直接给模型 |
| Component Detail Log | MCP、模型、数据库、Skill、SubAgent、SSE、缓存等底层组件细节 | 不直接给模型 |
| Development Log | Codex/SubAgent 开发过程、任务、验证、问题、验收 | 给开发者和主 Agent 调度使用 |

## 写入目标

P0 使用双写策略：

```text
本地热日志 = 系统故障时立即排查，尤其是 MinIO 不可用时仍可看。
MinIO 归档日志 = 长期查询、前端日志页、诊断包、跨实例排障。
```

本地热日志路径：

```text
runtime-data/logs/{runtime_instance_id}/system_summary.log
runtime-data/logs/{runtime_instance_id}/system_full.jsonl
runtime-data/logs/{runtime_instance_id}/errors.jsonl
runtime-data/logs/{runtime_instance_id}/components/{component}.jsonl
runtime-data/logs/{runtime_instance_id}/mcp/{server_name}.stderr.log
runtime-data/logs/{runtime_instance_id}/commands/{operation_id}.stdout.log
runtime-data/logs/{runtime_instance_id}/commands/{operation_id}.stderr.log
runtime-data/logs/{runtime_instance_id}/diagnostics/{bundle_id}/manifest.json
```

MinIO 归档路径：

```text
system/logs/{date}/{runtime_instance_id}/system_summary/part-000001.log
system/logs/{date}/{runtime_instance_id}/system_full/part-000001.jsonl
system/logs/{date}/{runtime_instance_id}/errors/part-000001.jsonl
system/logs/{date}/{runtime_instance_id}/components/{component}/part-000001.jsonl
system/logs/{date}/{runtime_instance_id}/diagnostic_bundles/{bundle_id}/manifest.json
system/logs/{date}/{runtime_instance_id}/diagnostic_bundles/{bundle_id}/bundle.zip

workspaces/{workspace_id}/runs/{run_id}/events/part-000001.jsonl
workspaces/{workspace_id}/runs/{run_id}/operations.jsonl
workspaces/{workspace_id}/runs/{run_id}/errors.jsonl
workspaces/{workspace_id}/runs/{run_id}/skill_runs/{skill_run_id}/stdout.txt
workspaces/{workspace_id}/runs/{run_id}/skill_runs/{skill_run_id}/stderr.txt
```

规则：

- 系统进程启动、配置加载、后台任务、MinIO 连接失败等无 workspace 的日志写 `system/logs`。
- 已知 `workspace_id` / `run_id` 的日志同时带上下文字段，并可在前端按 workspace 过滤。
- 大 stdout / stderr 不直接塞进 `system_full.jsonl`，只写摘要和 `artifact_object_key`。
- MinIO 上传失败时，本地热日志继续写，后台 LogShipper 稍后补传。

## 日志文件职责

| 文件 | 内容 | 默认级别 | 用途 |
| --- | --- | --- | --- |
| `system_summary.log` | 人类可快速阅读的简略日志 | INFO+ | 快速定位系统在做什么 |
| `system_full.jsonl` | 结构化完整运行日志 | DEBUG+，生产默认 INFO+ | 详细排障、检索、诊断包 |
| `errors.jsonl` | WARNING / ERROR / FATAL | WARNING+ | 故障快查 |
| `components/{component}.jsonl` | 单组件细节 | DEBUG+ 可配置 | 排查 MCP、数据库、模型、SSE 等底层问题 |
| `mcp/{server}.stderr.log` | MCP 子进程 stderr 截断日志 | INFO+ | MCP 启动失败、运行失败排查 |
| `commands/{operation_id}.stdout.log` | 命令 stdout 原文或截断原文 | 按 operation | 命令行工具排查 |
| `commands/{operation_id}.stderr.log` | 命令 stderr 原文或截断原文 | 按 operation | 命令行工具排查 |

## Trace / Span 规则

P0 不强制接 OpenTelemetry 服务，但内部日志必须按 trace/span 结构写，后续可无损导出 OTLP。

```text
trace_id = 一次用户请求或后台任务的全链路 ID
span_id = 一个组件动作，例如 model_call、tool_execute、milvus_search
parent_span_id = 上游 span
```

典型链路：

```text
REST POST /threads/{thread_id}/runs
  trace_id=trace_001 span=api_create_run
    -> langgraph_run_start span=graph_run
      -> build_context span=context_preflight
      -> model_call span=model_main_chat
      -> tool_execute span=tool_rag_search
        -> embedding_call span=embedding_query
        -> milvus_search span=milvus_search
        -> minio_read_chunk span=minio_read
        -> neo4j_expand span=neo4j_query
      -> sse_emit span=sse_send
```

## Redaction 规则

所有日志 sink 前必须经过统一 `RedactionFilter`。

禁止写入：

```text
API key
Authorization
Cookie
Set-Cookie
X-API-Key
access_token
refresh_token
数据库密码
AGENT_MASTER_KEY
Secret 明文
Secret 密文 / nonce / tag
完整 embedding 向量
完整用户隐私数据
完整原始文件内容
```

允许写入：

```text
secret_ref
masked
args_hash
payload_bytes
payload_hash
object_key
error_type
safe error message
```

LLM debug：

- `DEBUG_LLM=false` 是默认值。
- P0 不允许在生产环境开启完整 LLM 请求/响应日志。
- 开发环境如果开启，必须二次确认，并且仍走脱敏。
- 完整 prompt / response 默认不写系统日志；需要调试时写入受控诊断包，并标记 `sensitive=true`、默认不进入前端普通日志页。

## Python 日志初始化伪代码

```python
import contextvars
import logging
from logging.handlers import RotatingFileHandler

log_context = contextvars.ContextVar("log_context", default={})

def set_log_context(**kwargs):
    current = dict(log_context.get())
    current.update({k: v for k, v in kwargs.items() if v is not None})
    log_context.set(current)

class ContextFilter(logging.Filter):
    def filter(self, record: logging.LogRecord) -> bool:
        ctx = log_context.get()
        for key in [
            "runtime_instance_id", "trace_id", "span_id", "parent_span_id",
            "user_id", "role", "workspace_id", "thread_id", "run_id",
            "tool_call_id", "operation_id", "component",
        ]:
            setattr(record, key, ctx.get(key))
        return True

def setup_logging(config: LoggingConfig) -> None:
    root = logging.getLogger()
    root.setLevel(config.root_level)

    redactor = RedactionFilter()
    context_filter = ContextFilter()

    summary = RotatingFileHandler(config.local_dir / "system_summary.log", maxBytes=10_000_000, backupCount=5)
    summary.setLevel(logging.INFO)
    summary.setFormatter(SummaryFormatter())
    summary.addFilter(redactor)
    summary.addFilter(context_filter)

    full = RotatingFileHandler(config.local_dir / "system_full.jsonl", maxBytes=50_000_000, backupCount=10)
    full.setLevel(config.full_level)
    full.setFormatter(JsonLogFormatter())
    full.addFilter(redactor)
    full.addFilter(context_filter)

    errors = RotatingFileHandler(config.local_dir / "errors.jsonl", maxBytes=20_000_000, backupCount=5)
    errors.setLevel(logging.WARNING)
    errors.setFormatter(JsonLogFormatter())
    errors.addFilter(redactor)
    errors.addFilter(context_filter)

    root.addHandler(summary)
    root.addHandler(full)
    root.addHandler(errors)
```

```python
async def observability_middleware(request, call_next):
    trace_id = request.headers.get("x-trace-id") or new_trace_id()
    set_log_context(
```

## LangGraph 节点日志伪代码

```python
def logged_node(component: str, node_name: str, fn):
    def wrapper(state: AgentState) -> dict:
        span_id = new_span_id()
        set_log_context(
            component=component,
            trace_id=state["trace_id"],
            span_id=span_id,
            parent_span_id=state.get("current_span_id"),
            workspace_id=state["workspace_id"],
            thread_id=state["thread_id"],
            run_id=state["run_id"],
        )
        logger.info("LangGraph node started", extra={"event_type": "graph_node_started", "node": node_name})
        started = monotonic_ms()
        try:
            result = fn(state)
            logger.info("LangGraph node finished", extra={
                "event_type": "graph_node_finished",
                "node": node_name,
                "duration_ms": monotonic_ms() - started,
            })

            logger.exception("LangGraph node failed", extra={
                "event_type": "graph_node_failed",
                "node": node_name,
                "error_type": classify_error(exc),
            })
            raise
    return wrapper
```

## MCP / 命令行日志规则

MCP：

```text
mcp_client 记录 connect / initialize / list_tools / call_tool / disconnect。
stderr 原文写本地 mcp/{server}.stderr.log，并按大小截断和脱敏。
system_full.jsonl 只记录 stderr_preview、stderr_bytes、stderr_hash。
```

命令行 / 沙盒：

```text
stdout/stderr 原文写 commands/{operation_id}.stdout.log 和 stderr.log。
system_full.jsonl 只记录 command_preview、exit_code、duration_ms、out_bytes、out_hash、err_bytes、err_hash。
高风险命令必须关联 operation_id、approval_id、rollback_token。
```

命令日志摘要伪代码：

```python
def log_command_finished(operation_id: str, result: CommandResult):
    stdout_ref = artifact_store.write_command_stdout(operation_id, result.stdout)
    stderr_ref = artifact_store.write_command_stderr(operation_id, result.stderr)
    logger.info("Command finished", extra={
        "component": "sandbox",
        "event_type": "command_finished",
        "operation_id": operation_id,
        "exit_code": result.exit_code,
        "duration_ms": result.duration_ms,
        "stdout_bytes": len_bytes(result.stdout),
        "stdout_hash": sha256_short(result.stdout),
        "stderr_bytes": len_bytes(result.stderr),
        "stderr_hash": sha256_short(result.stderr),
        "stdout_ref": stdout_ref,
        "stderr_ref": stderr_ref,
```

## LogShipper

`LogShipper` 把本地热日志异步归档到 MinIO。P0 归档动作由 `log_shipper_job` 执行，Job 失败不阻断主系统，本地热日志继续写。

流程：

```text
1. 监听本地 log 文件轮转。
2. 已封存文件计算 sha256。
3. 上传到 system/logs/{date}/{runtime_instance_id}/...
4. 写 shipper manifest。
5. 上传失败时记录本地 errors.jsonl，指数退避重试。
6. MinIO 恢复后补传。
```

`shipper manifest`：

```json
{
  "schema_version": 1,
  "runtime_instance_id": "rt_001",
  "date": "2026-05-30",
  "files": [
    {
      "local_path": "runtime-data/logs/rt_001/system_full.jsonl.1",
      "object_key": "system/logs/2026-05-30/rt_001/system_full/part-000001.jsonl",
      "sha256": "sha256...",
      "uploaded_at": "2026-05-30T16:30:00+08:00"
    }
  ]
}
```

## 前端系统日志页

P0 在日志审计页面中增加 `系统日志` Tab，或独立 `系统运行日志` 页面。

功能：

- 选择时间范围。
- 选择 level：TRACE / DEBUG / INFO / WARN / ERROR / FATAL。
- 选择 component。
- 按 trace_id / run_id / operation_id / mcp_server 搜索。
- 查看 system summary。
- 查看 full JSONL 的脱敏字段。
- 查看 errors 快查。
- auto-follow 最新日志。
- 导出当前筛选结果。
- 生成诊断包。

接口：

## 模型可用的安全日志工具

模型不能读取完整系统日志，只能调用受控工具：

| Tool | 返回 |
| --- | --- |
| `safe_log_search` | 脱敏摘要、错误分类、trace_id |
| `system_health_snapshot` | 当前组件健康状态 |
| `database_health_check` | MinIO / Milvus / Neo4j 脱敏状态 |
| `mcp_health_check` | MCP server 脱敏状态 |
| `run_failure_summary` | 指定 run 的失败摘要 |

`safe_log_search` 伪代码：

```python
class SafeLogSearchArgs(BaseModel):
    workspace_id: str
    trace_id: str | None = None
    run_id: str | None = None
    component: str | None = None
    error_type: str | None = None
    query: str | None = None
    limit: int = Field(default=20, le=50)

@tool("safe_log_search", args_schema=SafeLogSearchArgs)
def safe_log_search_tool(**args) -> dict:
    assert_user_can_read_workspace(current_user.id, args["workspace_id"])
    rows = system_log_reader.search(**args)
    safe_rows = [summarize_log_row(redact(row)) for row in rows]
    return ToolResult.ok({
        "items": safe_rows,
        "redacted": True,
        "message_for_model": "Only redacted log summaries are returned."
    }).to_dict()
```

## 保留周期

| 日志 | 本地保留 | MinIO 保留 |
| --- | --- | --- |
| system_summary | 14 天 | 90 天 |
| system_full | 7 天 | 30 天 |
| errors | 30 天 | 180 天 |
| component debug | 3 天 | 14 天 |
| MCP stderr | 7 天 | 30 天 |
| command stdout/stderr | 跟随 run artifact | 跟随 run artifact |
| diagnostic bundle | 7 天 | 30 天 |
| run event / operations | 不按系统日志清理 | 跟随 workspace 数据保留策略 |

## 验收标准

- MinIO 停止时，系统仍写本地 `system_full.jsonl` 和 `errors.jsonl`。
- 每个 HTTP 请求都有 trace_id。
- 每个 run、tool call、model call、MCP call 都能通过 trace_id 串起来。
- 前端能按 component / level / trace_id 查询系统日志。
- 错误日志不包含 API key、Authorization、Cookie、Secret 明文或密文。
- 命令 stdout/stderr 大内容不会塞进系统 JSONL，只保存摘要和 artifact 引用。
- MCP stderr 可以查看 preview，但默认不展示完整原文。
- 诊断包可生成，且 manifest 标记 `redacted=true`。
