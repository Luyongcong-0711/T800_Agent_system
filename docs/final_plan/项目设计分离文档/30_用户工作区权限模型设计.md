# 用户、工作区与权限模型设计

## 当前决策

P0 按单用户系统开发，但数据结构保留 `user_id` 和 `role`。

```text
P0 不做登录页。
P0 不做注册、邀请、团队协作和复杂 RBAC。
P0 默认只有一个 workspace。
P0 前端不做复杂 workspace 切换。
所有数据路径、API、Tool 参数、日志和审计记录都保留 workspace_id。
```

默认身份：

```text
user_id = default_user
role = owner
workspace_id = default
workspace_role = owner
```

`workspace` 不是对话窗口。`workspace` 是项目空间，`thread` 才是一个对话窗口。

## 概念层级

```text
User
  -> Workspace
      -> Thread
          -> Run
              -> Event
      -> KnowledgeBase
          -> Document
          -> Chunk
      -> Memory
      -> Config
      -> MCP Policy
      -> Skill Policy
      -> Audit Log
```

| 概念 | 含义 | P0 行为 |
| --- | --- | --- |
| User | 使用系统的人 | 默认 `default_user`，不登录 |
| Role | 用户在系统或 workspace 中的角色 | 默认 `owner`，字段保留 |
| Workspace | 一个项目空间，隔离知识库、对话、配置、日志和项目记忆 | 默认只有 `default` |
| Thread | workspace 里的一个可见对话窗口 | 支持多 thread |
| Run | thread 里用户提交一次消息后触发的一次 Agent 执行 | 每次提交生成一个 run |
| Message | thread 消息流中的持久化消息 | 保存在 `sessions/{thread_id}/messages` |
| Event | run 内部事件，用于 SSE、工具状态、审批和审计 | 保存在 `runs/{run_id}/events` |

## Workspace 边界

Workspace 是主要数据隔离边界。P0 虽然默认只有一个 workspace，但所有接口必须保留 `workspace_id`。

一个 workspace 包含：

- thread 和历史对话。
- run 和运行事件。
- 上传文件。
- 知识库。
- 文档、chunk、实体、关系和 evidence。
- 模型配置。
- 数据库连接配置。
- MCP server capability snapshot 和单 tool policy。
- Skill manifest、版本和执行记录。
- SubAgent 配置和运行记录。
- 项目长期记忆。
- 日志、审计和恢复索引。

## Role 模型

P0 只启用 `owner`。

保留角色枚举：

```text
owner
admin
editor
viewer
```

P0 代码仍必须调用权限检查函数，不能因为单用户就绕过 scope guard。

## 身份注入

P0 不做登录页。Agent Server 启动时创建默认身份上下文：

```json
{
  "user_id": "default_user",
  "display_name": "Default User",
  "role": "owner",
  "default_workspace_id": "default"
}
```

前端启动时调用 bootstrap 接口：

```http
GET /bootstrap
```

返回：

```json
{
  "current_user": {
    "user_id": "default_user",
    "role": "owner",
    "display_name": "Default User"
  },
  "current_workspace": {
    "workspace_id": "default",
    "name": "Default Workspace",
    "role": "owner"
  },
  "features": {
    "login_enabled": false,
    "workspace_switch_enabled": false,
    "multi_user_enabled": false
  }
}
```

前端把 `workspace_id=default` 写入全局 store。之后所有 workspace 级 API 都从 store 读取 `workspace_id` 并带给后端。

## API Scope 规则

P0 所有 workspace 级 API 必须带 `workspace_id`。

示例：

```http
GET /workspaces/{workspace_id}/threads
POST /workspaces/{workspace_id}/threads
GET /workspaces/{workspace_id}/threads/{thread_id}
POST /workspaces/{workspace_id}/threads/{thread_id}/runs
GET /workspaces/{workspace_id}/runs/{run_id}
GET /workspaces/{workspace_id}/runs/{run_id}/events
GET /workspaces/{workspace_id}/memory
GET /workspaces/{workspace_id}/knowledge-bases
POST /workspaces/{workspace_id}/database/test
GET /workspaces/{workspace_id}/mcp/servers
```

全局用户级 API 不带 workspace_id：

```http
GET /users/{user_id}/profile
GET /users/{user_id}/preferences/global
PATCH /users/{user_id}/profile/{memory_id}
```

P0 前端通常不直接传 `user_id`，后端从 `RuntimeIdentity` 读取当前用户。Tool 参数中仍保留 `user_id`，用于审计、记忆归属和未来多用户扩展。

## 权限检查伪代码

P0 是单用户，但权限检查函数仍然必须存在。

```python
from dataclasses import dataclass

@dataclass(frozen=True)
class RuntimeIdentity:
    user_id: str
    role: str
    workspace_id: str
    workspace_role: str

DEFAULT_IDENTITY = RuntimeIdentity(
    user_id="default_user",
    role="owner",
    workspace_id="default",
    workspace_role="owner",
)

class AccessDenied(Exception):
    pass

def get_current_identity() -> RuntimeIdentity:
    # P0 no login: return bootstrap identity.
    # P1 replaces this with auth middleware.
    return DEFAULT_IDENTITY

def assert_current_user(user_id: str) -> None:
    identity = get_current_identity()
    if user_id != identity.user_id:
        raise AccessDenied("user_id does not match current identity")

def assert_user_can_read_workspace(user_id: str, workspace_id: str) -> None:
    identity = get_current_identity()
    if user_id != identity.user_id:
        raise AccessDenied("invalid user")
    if workspace_id != identity.workspace_id:
        raise AccessDenied("workspace is not available in P0")
    if identity.workspace_role not in {"owner", "admin", "editor", "viewer"}:
        raise AccessDenied("role cannot read workspace")

def assert_user_can_manage_workspace(user_id: str, workspace_id: str) -> None:
    identity = get_current_identity()
    assert_user_can_read_workspace(user_id, workspace_id)
    if identity.workspace_role not in {"owner", "admin"}:
        raise AccessDenied("role cannot manage workspace")

def assert_user_can_approve(user_id: str, workspace_id: str) -> None:
    identity = get_current_identity()
    assert_user_can_read_workspace(user_id, workspace_id)
    if identity.workspace_role != "owner":
        raise AccessDenied("only owner can approve P0 high-risk actions")
```

LangChain Tool 中必须调用 scope guard：

```python
from langchain_core.tools import tool
from pydantic import BaseModel, Field

class ThreadListArgs(BaseModel):
    workspace_id: str = Field(..., description="当前 workspace ID")
    status: list[str] = Field(default_factory=lambda: ["active"])

@tool("thread_list", args_schema=ThreadListArgs)
def thread_list_tool(workspace_id: str, status: list[str] | None = None) -> dict:
    """列出当前 workspace 下的对话窗口摘要。"""
    identity = get_current_identity()
    assert_user_can_read_workspace(identity.user_id, workspace_id)
    threads = thread_service.list_threads(workspace_id=workspace_id, statuses=status or ["active"])
    return ToolResult.ok({"threads": [t.public_dict() for t in threads]}).to_dict()
```

LangGraph state 必须携带身份和 workspace：

## Memory Scope

长期记忆按 scope 分层：

| 类型 | Scope | 归属 | 默认是否跨 thread 注入 |
| --- | --- | --- | --- |
| `user_profile` | `global` | 用户级 | 是 |
| `user_preference` | `global` 或 `workspace` | 用户级或工作区级 | 是，受 scope 过滤 |
| `project_fact` | `workspace` | 工作区级 | 是，当前 workspace 内注入 |
| `project_rule` | `workspace` | 工作区级 | 是，当前 workspace 内注入 |
| `tool_usage_preference` | `global` 或 `workspace` | 用户级或工作区级 | 按工具上下文注入 |
| `correction` | `workspace` | 工作区级 | 按相关任务注入 |
| `relationship_fact` | `workspace` | 工作区级 | 按 GraphRAG / memory 检索注入 |

规则：

- `user_profile` 永远是全局，例如名字、称呼。
- `user_preference` 支持全局和 workspace 两种 scope。
- “用户喜欢中文回复”属于 `global user_preference`。
- “这个项目必须使用 LangChain + LangGraph”属于 `workspace user_preference` 或 `project_rule`。
- `project_fact` / `project_rule` 永远是 workspace 级。
- 新建 thread 时不会继承旧 thread 的短期上下文，但会注入启用状态的 global memory 和当前 workspace memory。

## Memory Snapshot 组装顺序

每次模型调用前，Runtime 组装 memory snapshot：

```text
1. global user_profile
2. global user_preference
3. 当前 workspace 的 user_preference
4. 当前 workspace 的 project_rule
5. 当前 workspace 的 project_fact 摘要
6. 根据当前 query 检索到的 memory_search 摘要
```

伪代码：

```python
def build_memory_snapshot(user_id: str, workspace_id: str, query: str) -> dict:
    assert_current_user(user_id)
    assert_user_can_read_workspace(user_id, workspace_id)

    global_profile = memory_store.list_enabled(
        user_id=user_id,
        scope="global",
        memory_types=["user_profile"],
    )
    global_preferences = memory_store.list_enabled(
        user_id=user_id,
        scope="global",
        memory_types=["user_preference"],
    )
    workspace_memories = memory_store.list_enabled(
        user_id=user_id,
        workspace_id=workspace_id,
        scope="workspace",
        memory_types=["user_preference", "project_rule", "project_fact"],
    )
    retrieved = memory_search_service.search(
        user_id=user_id,
        workspace_id=workspace_id,
        query=query,
        limit=8,
    )

    snapshot = MemorySnapshot.from_parts(
        global_profile=global_profile,
        global_preferences=global_preferences,
        workspace_memories=workspace_memories,
        retrieved=retrieved,
    )
    minio.write_json(memory_snapshot_key(workspace_id, snapshot.snapshot_id), snapshot.to_dict())
    return snapshot.to_dict()
```

## 前端行为

P0 前端：

- 不显示登录页。
- 启动时调用 `/bootstrap`。
- 默认进入 `workspace_id=default`。
- 不显示复杂 workspace 切换器。
- 所有 API Client 自动带上 `workspace_id`。
- Memory 页面需要区分“全局记忆”和“当前 workspace 记忆”。
- 主对话页左侧显示的是当前 workspace 下的 thread 列表，不是全局所有 thread。

前端 store：

```ts
type IdentityState = {
  userId: string;
  role: 'owner' | 'admin' | 'editor' | 'viewer';
  workspaceId: string;
  workspaceRole: 'owner' | 'admin' | 'editor' | 'viewer';
  loginEnabled: boolean;
  workspaceSwitchEnabled: boolean;
};
```

Agent API Client 自动注入 workspace：

```ts
export class AgentApiClient {
  constructor(private readonly identityStore: IdentityStore) {}

  async listThreads(): Promise<ThreadSummary[]> {
    const { workspaceId } = this.identityStore.getState();
    return this.get(`/workspaces/${workspaceId}/threads`);
  }

  async createRun(threadId: string, input: CreateRunInput): Promise<RunDetail> {
    const { workspaceId } = this.identityStore.getState();
    return this.post(`/workspaces/${workspaceId}/threads/${threadId}/runs`, input);
  }
}
```

## P1 扩展边界

后续要从 P0 单用户升级到多用户时，优先新增：

- 登录和 Auth middleware。
- Workspace 切换器。
- Workspace 成员管理。
- RBAC 权限矩阵。
- 密钥访问权限。
- 审计中的 actor / service account。

P0 已保留 `user_id`、`role`、`workspace_id`、`members.json` 和 scope guard，因此升级时主要替换身份来源，不需要重构业务对象路径。
