## 定位

本文件定义真实开发仓库的目录结构、模块边界和首批文件创建顺序。它把前面 00 到 35 的设计落成可以直接 scaffold 的工程树。

## 仓库根目录

真实代码项目放在当前设计工作目录下的 `agent-system/`：

```text
C:\Users\Administrator\Desktop\Agent design\前期技术栈设计\agent-system
```

`final_plan/` 只保存开发前最终设计资料，不放运行时代码。开发开始后，代码仓库结构如下：

```text
agent-system/
  backend/
  frontend/
  deploy/
  scripts/
  docs/
  tests/
  .env.example
  docker-compose.yml
  README.md
```

规则：

- `backend` 是 Python + FastAPI + LangChain + LangGraph。
- `frontend` 是 React + TypeScript + Next.js + pnpm + @lobehub/ui + Antd + antd-style。
- `deploy` 保存 docker compose、初始化脚本和本地开发依赖配置。
- `docs` 保存从 `..\final_plan\项目设计分离文档` 拷贝出来的开发参考快照，不作为运行时依赖。
- `tests` 只放跨服务 E2E 和验收测试；后端/前端自己的单元测试放各自目录。

建议首次 scaffold 后执行：

```text
agent-system/
  docs/final_plan/项目设计分离文档/
```

这样开发仓库内部也有一份只读设计快照，方便代码审查和 CI 文档检查；但权威源仍是 `..\final_plan\项目设计分离文档`。

## 首批 scaffold 顺序

1. 创建 `backend/app/core`、`backend/app/schemas`、`backend/app/storage`。
2. 创建 `backend/app/main.py` 和 `/bootstrap`。
3. 创建 `deploy/compose/docker-compose.local.yml`。
4. 创建 `frontend/app/providers.tsx` 和默认 workspace layout。
5. 创建 `backend/app/storage/minio_store.py`。
6. 创建 Secret Store。
7. 创建 Model Provider Adapter。
8. 创建 Run/Event/SSE。
9. 创建 JobStore 和 Jobs API。

## 模块依赖规则

```text
api -> service/runtime/job/storage
runtime -> model_connector/tools/events/memory
jobs -> storage/rag_pipeline/graph_pipeline/mcp_client/observability
tools -> storage/memory/graph_pipeline/rag_pipeline/mcp_client
frontend -> api adapter -> backend api
```

禁止：

- `api` 直接写 MinIO 复杂对象，必须走 service/store。
- `model_connector` 调用 Tool。
- `frontend` 直接拼接 MinIO object key。
- `Tool` 直接解析 Secret 明文。
- `Skill Script` 直接连接数据库。

## 代码命名规则

- Python 包名使用 snake_case。
- Pydantic schema 文件按业务域分组。
- 后端 service 类用 `XxxService`。
- Store 类用 `XxxStore`。
- Connector 类用 `XxxConnector`。
- 前端组件使用 PascalCase。
- 前端 Zustand store 使用 `useXxxStore.ts`。
