# 数据库接口规范与数据库工具设计

## 总原则

模型不能直接连接数据库。

数据库必须通过 Runtime 暴露的 Tool 调用：

```text
LLM
  -> tool call
  -> Tool Executor
  -> Connector
  -> MinIO / Milvus / Neo4j
```

所有数据库工具必须：

- 校验 workspace_id。
- 校验权限。
- 限制查询范围。
- 设置 timeout。
- 返回 ToolResult。
- 写入脱敏日志。
- 对失败做分类。
- 通过内部 SecretResolver 解析数据库凭据；模型、Tool 参数、ToolResult 和日志不能包含明文连接凭据。

模型可调用的数据库能力统一用 LangChain Tool 暴露；底层数据库 SDK、连接池、重试和错误分类放在 Connector / Service 中。

公共骨架：

```python
from langchain_core.tools import tool
from pydantic import BaseModel, Field

class DatabaseScopeArgs(BaseModel):
    workspace_id: str = Field(..., description="当前工作区 ID")
    knowledge_base_id: str | None = Field(default=None, description="当前知识库 ID")

def finish_database_tool(tool_name: str, result: ToolResult, params_preview: dict | None = None) -> dict:
    runtime_services.audit_log.write_tool_event(
        tool_name,
        params_preview=redact(params_preview or {}),
        result_summary=summarize_result(result),
    )
    return result.to_dict()
```

## MinIO 接口规范

Connector 方法：

```text
health_check()
```

工具：

| 工具 | 说明 | 风险 |
| --- | --- | --- |
| object_store_get | 读取指定 object 摘要或内容 | low / medium |
| object_store_put_artifact | 写入运行产物 | medium |
| object_store_list | 按 prefix 列出对象 | low |
| manifest_get | 读取文档 manifest | low |
| versions_get | 读取文档版本历史 | low |
| workspace_index_get | 读取工作区索引入口 | low |
| documents_index_get | 读取文档列表摘要 | low |
| runs_index_get | 读取运行任务列表摘要 | low |
| run_manifest_get | 读取 run manifest | low |
| run_leaf_state_get | 读取 run 当前可恢复快照 | low |
| run_events_page_get | 按 after_event_id 分页读取 run 事件 | low |
| run_event_index_rebuild | 重建单个 run 的 event_index / leaf_state | medium |
| memory_index_get | 读取长期记忆列表摘要 | low |
| memory_object_get | 按 memory_id 读取长期记忆权威 JSON | low / medium |
| memory_object_upsert | 写入或更新长期记忆权威 JSON | medium |
| memory_object_delete | 删除或禁用长期记忆 | medium / high |
| memory_snapshot_write | 写入本次模型调用注入的 memory snapshot | low |
| chunk_get | 按 chunk_id 回源正文 | low |
| entity_resolution_decisions_get | 读取实体归一化决策记录 | low |

失败策略：

- 读取 timeout 可重试。
- object 不存在不可重试，但不是系统崩溃。
- 上传中断优先 multipart resume。
- 删除操作高风险，需要审批。
- 索引文件更新失败时，保留已写入的权威对象，记录错误并允许重建索引。
- 前端列表读取索引文件，详情页再读取 manifest、events、operations 或 memory 原文。
- `run_events_page_get` 必须只通过 `event_index.json` 定位 `events/part-*.jsonl`，不能扫描整个 workspace。
- `run_event_index_rebuild` 只能由系统恢复任务、管理员诊断或受控后台任务调用，不能暴露给普通模型自由调用。
- `append_run_event` 只允许 Runtime 内部 EventStoreWriter 调用，不暴露给 LLM。
- `write_event_index`、`write_leaf_state` 必须使用 etag / revision 乐观并发控制。
- run ownership 失败时不得继续写入该 run。
- `user_profile` / global `user_preference` 写入不需要审批，但必须更新 `users/{user_id}/indexes/memory_index.json` 并写入用户可见事件。
- workspace `user_preference`、`project_fact`、`project_rule` 写入必须更新 `workspaces/{workspace_id}/indexes/memory_index.json`。
- 删除或禁用记忆后，下一次模型调用的 memory snapshot 不能再包含对应 memory_id。

Catalog 类工具不连接额外数据库，而是读取 MinIO 中的 JSON / JSONL：

| 工具 | 读取对象 |
| --- | --- |
| catalog_list_documents | `documents_index.json` |
| catalog_get_document | `manifest.json` + `versions.json` |
| catalog_list_runs | `runs_index.json` |
| catalog_get_ingestion_trace | `documents/{doc_id}/events/ingestion.jsonl` + run errors |
| catalog_get_run_events | `event_index.json` + `events/part-*.jsonl` |
| catalog_get_run_leaf_state | `leaf_state.json` |
| catalog_get_chunk_metadata | `chunks.json` |
| catalog_get_resolution_decisions | `entity_resolution_decisions.jsonl` |
| catalog_list_memories | `memory_index.json` |
| catalog_get_memory | `memory/{memory_id}.json` |
| catalog_get_memory_snapshot | `sessions/{thread_id}/memory_snapshots/{snapshot_id}.json` |

- 写入失败使用 `operation_id` 去重。

### vector_search LangChain Tool

`vector_search` 是模型可调用的低风险检索工具。它不让模型传入任意 collection 名，默认使用知识库 active embedding 版本对应的 active collection；更换 embedding 模型时必须新建 collection 并重新入库。

请求：

```json
{
  "workspace_id": "default",
  "knowledge_base_id": "kb_default",
  "query": "GraphRAG 如何扩展关系？",
  "top_k": 20,
  "filters": {"doc_id": "doc_001"},
  "include_query_embedding": false
}
```

返回：

```json
{
  "collection": "kb_default_text_embedding_v4_1024",
  "embedding": {
    "provider": "openai_compatible",
    "model": "text-embedding-v4",
    "base_url": "https://dashscope.aliyuncs.com/compatible-mode/v1",
    "dimension": 1024
  },
  "hits": [
    {
      "chunk_id": "doc_001_chunk_0001",
      "doc_id": "doc_001",
      "object_key": "workspaces/default/documents/doc_001/chunks/chunk-0001.json",
      "score": 0.82
    }
  ],
  "warnings": []
}
```

LangChain Tool 伪代码：

```python
class VectorSearchArgs(DatabaseScopeArgs):
    knowledge_base_id: str
    query: str
    top_k: int = Field(default=20, ge=1, le=100)
    filters: dict = Field(default_factory=dict)
    include_query_embedding: bool = False

@tool("vector_search", args_schema=VectorSearchArgs)
def vector_search_tool(
    workspace_id: str,
    knowledge_base_id: str,
    query: str,
    top_k: int = 20,
    filters: dict | None = None,
    include_query_embedding: bool = False,
) -> dict:
    """使用知识库 active embedding collection 做 Milvus 向量检索，只返回检索摘要和回源路径。"""
    assert_scope(workspace_id, knowledge_base_id)
    active_embedding = kb_store.get_active_embedding(knowledge_base_id)
    query_vector = embedding_client.embed_query(
        text=query,
        provider=active_embedding.provider,
        model=active_embedding.model,
        dimension=active_embedding.dimension,
    )
    hits = milvus.search(
        collection=active_embedding.collection,
        vector=query_vector,
        top_k=clamp(top_k, 1, 100),
        filters={
            "workspace_id": workspace_id,
            "knowledge_base_id": knowledge_base_id,
            **(filters or {}),
        },
    )
    data = {
        "collection": active_embedding.collection,
        "embedding": active_embedding.public_summary(),
        "hits": [hit.public_dict() for hit in hits],
        "warnings": [],
    }
    if include_query_embedding:
        snapshot_key = minio.write_query_embedding_snapshot(workspace_id, knowledge_base_id, query_vector)
        data["query_embedding_snapshot_key"] = snapshot_key

    result = ToolResult.ok(data)
    return finish_database_tool("vector_search", result, {"knowledge_base_id": knowledge_base_id, "top_k": top_k})
```

### document_chunk_get LangChain Tool

`document_chunk_get` 用于根据 `chunk_id` 或 `object_key` 回源 MinIO chunk 正文。模型不能自由列 MinIO 全路径，必须先通过检索结果、引用或前端上下文拿到 chunk 标识。

LangChain Tool 伪代码：

```python
class DocumentChunkGetArgs(DatabaseScopeArgs):
    knowledge_base_id: str
    chunk_id: str | None = None
    object_key: str | None = None
    max_chars: int = Field(default=1200, ge=200, le=4000)

@tool("document_chunk_get", args_schema=DocumentChunkGetArgs)
def document_chunk_get_tool(
    workspace_id: str,
    knowledge_base_id: str,
    chunk_id: str | None = None,
    object_key: str | None = None,
    max_chars: int = 1200,
) -> dict:
    """从 MinIO 回源读取 chunk 正文，返回可引用证据。"""
    assert_scope(workspace_id, knowledge_base_id)
    resolved_key = object_key or chunk_index.resolve_object_key(workspace_id, knowledge_base_id, chunk_id)
    assert_object_key_in_kb_scope(resolved_key, workspace_id, knowledge_base_id)
    chunk = minio.read_json(resolved_key)
    result = ToolResult.ok({
        "chunk_id": chunk["chunk_id"],
        "doc_id": chunk["doc_id"],
        "doc_version_id": chunk["doc_version_id"],
        "source": chunk["source"],
        "text": truncate(chunk["text"], max_chars),
    })
    return finish_database_tool("document_chunk_get", result, {"chunk_id": chunk_id, "object_key": resolved_key})
```

## Neo4j 接口规范

Connector 方法：

```text
health_check()
get_schema_snapshot(workspace_id, knowledge_base_id)
entity_search(workspace_id, knowledge_base_id, query, entity_types, limit)
resolve_entity(workspace_id, knowledge_base_id, name_or_id, entity_types)
expand_entity(workspace_id, knowledge_base_id, entity_id, depth, relationship_allowlist, limit)
find_direct_relationships(workspace_id, knowledge_base_id, source_entity_id, target_entity_id, relationship_allowlist, limit)
find_paths(workspace_id, knowledge_base_id, source_entity_id, target_entity_id, max_depth, relationship_allowlist, limit)
get_evidence_refs(workspace_id, knowledge_base_id, fact_ids, evidence_ids, limit)
timeline_query(workspace_id, knowledge_base_id, entity_id, date_from, date_to, limit)
write_graph_batch_internal(batch, operation_id, caller_type)
readonly_query_admin(cypher, params, timeout, user_id)
```

接口边界：

- 普通 LLM 只能调用参数化只读图谱工具。
- 普通 LLM 不能调用 `write_graph_batch_internal`。
- 普通 LLM 不能调用 `readonly_query_admin`。
- `write_graph_batch_internal` 只允许入库 pipeline、图谱重建任务、管理员维护任务调用。
- `readonly_query_admin` 只允许管理员诊断页调用，必须只读账号、白名单、timeout、LIMIT。

模型可调用的图谱工具优先按 LangChain Tool 形态实现。底层 Neo4jConnector 仍是普通 Python 服务，但暴露给模型的必须是 `@tool` / `StructuredTool` 包装后的受控能力。

LangChain Tool 基础结构：

```python
from langchain_core.tools import tool
from pydantic import BaseModel, Field

class GraphScopeArgs(BaseModel):
    workspace_id: str = Field(..., description="当前工作区 ID")
    knowledge_base_id: str = Field(..., description="当前知识库 ID")

def get_graph_services():
    return runtime_services.graph_query, runtime_services.minio, runtime_services.audit_log
```

```python
class GraphEntitySearchArgs(GraphScopeArgs):
    query: str = Field(..., description="实体名称、别名或关键词")
    entity_types: list[str] = Field(default_factory=list, description="允许的实体类型")
    limit: int = Field(default=10, ge=1, le=20)
    include_aliases: bool = True

@tool("graph_entity_search", args_schema=GraphEntitySearchArgs)
def graph_entity_search_tool(
    workspace_id: str,
    knowledge_base_id: str,
    query: str,
    entity_types: list[str] | None = None,
    limit: int = 10,
    include_aliases: bool = True,
) -> dict:
    """搜索图谱实体候选，只返回只读实体摘要和匹配证据数量。"""
    graph_query, _, audit_log = get_graph_services()
    assert_scope(workspace_id, knowledge_base_id)
    normalized_query = normalize_text(query)
    allowed_types = filter_allowed_labels(entity_types or [])
    safe_limit = clamp(limit, 1, 20)

    exact_hits = graph_query.entity_search(workspace_id, knowledge_base_id, normalized_query, allowed_types, safe_limit)
    alias_hits = []
    if include_aliases:
        alias_hits = graph_query.entity_alias_search(workspace_id, knowledge_base_id, normalized_query, allowed_types, safe_limit)
    merged = merge_rank_dedupe([exact_hits, alias_hits], key="entity_id")

    result = ToolResult.ok({"entities": merged[:safe_limit], "warnings": []})
    audit_log.write_tool_event("graph_entity_search", params_preview={"query": query}, result_summary=summarize_result(result))
    return result.to_dict()
```

### graph_expand_entity

请求：

```json
{
  "workspace_id": "default",
  "knowledge_base_id": "kb_default",
  "entity_id": "ent_001",
  "depth": 2,
  "relationship_allowlist": ["MEMBER_OF", "LIVES_IN", "PARTICIPATED_IN"],
  "limit": 30,
  "include_evidence": true
}
```

返回必须保留方向。弱关系需要带 `relation_strength=weak` 和 `rank_penalty`，由 Runtime 在合并证据时降权。

LangChain Tool 伪代码：

```python
class GraphExpandEntityArgs(GraphScopeArgs):
    entity_id: str
    depth: int = Field(default=1, ge=1, le=2)
    relationship_allowlist: list[str] = Field(default_factory=list)
    limit: int = Field(default=30, ge=1, le=50)
    include_evidence: bool = True

@tool("graph_expand_entity", args_schema=GraphExpandEntityArgs)
def graph_expand_entity_tool(
    workspace_id: str,
    knowledge_base_id: str,
    entity_id: str,
    depth: int = 1,
    relationship_allowlist: list[str] | None = None,
    limit: int = 30,
    include_evidence: bool = True,
) -> dict:
    """扩展单个实体周边 1 到 2 跳关系，返回方向、关系强弱和 evidence 引用。"""
    graph_query, _, audit_log = get_graph_services()
    assert_scope(workspace_id, knowledge_base_id)
    safe_depth = clamp(depth, 1, 2)
    safe_limit = clamp(limit, 1, 50)
    rels = filter_allowed_relationships(relationship_allowlist or [])

    entity = graph_query.resolve_entity(workspace_id, knowledge_base_id, entity_id, None)
    paths = graph_query.expand_entity(
        workspace_id,
        knowledge_base_id,
        entity.entity_id,
        safe_depth,
        rels,
        safe_limit * 3,
    )
    paths = [preserve_direction(path) for path in paths]
    paths = rank_graph_paths(paths)

    result = ToolResult.ok({"start_entity": entity.summary(), "paths": paths[:safe_limit]})
    audit_log.write_tool_event("graph_expand_entity", params_preview={"entity_id": entity_id}, result_summary=summarize_result(result))
    return result.to_dict()
```

### graph_find_relationship

请求：

```json
{
  "workspace_id": "default",
  "knowledge_base_id": "kb_default",
  "source_entity": "林黛玉",
  "target_entity": "贾宝玉",
  "relationship_allowlist": ["PARTICIPATED_IN", "MEMBER_OF"],
  "include_evidence": true
}
```

LangChain Tool 伪代码：

```python
class GraphFindRelationshipArgs(GraphScopeArgs):
    source_entity: str
    target_entity: str
    relationship_allowlist: list[str] = Field(default_factory=list)
    include_evidence: bool = True

@tool("graph_find_relationship", args_schema=GraphFindRelationshipArgs)
def graph_find_relationship_tool(
    workspace_id: str,
    knowledge_base_id: str,
    source_entity: str,
    target_entity: str,
    relationship_allowlist: list[str] | None = None,
    include_evidence: bool = True,
) -> dict:
    """查询两个实体之间的直接关系。遇到歧义实体时返回候选，不让模型猜。"""
    graph_query, _, audit_log = get_graph_services()
    assert_scope(workspace_id, knowledge_base_id)
    source = resolve_entity_or_disambiguate(source_entity, workspace_id, knowledge_base_id)
    target = resolve_entity_or_disambiguate(target_entity, workspace_id, knowledge_base_id)
    if source.needs_disambiguation or target.needs_disambiguation:
        return ToolResult.ok({"needs_disambiguation": True, "candidates": source.candidates + target.candidates}).to_dict()

    rels = graph_query.find_direct_relationships(
        workspace_id,
        knowledge_base_id,
        source.entity_id,
        target.entity_id,
        filter_allowed_relationships(relationship_allowlist or []),
        limit=20,
    )
    result = ToolResult.ok({
        "source": source.summary(),
        "target": target.summary(),
        "relationships": rank_relationships(rels),
        "empty": len(rels) == 0,
    })
    audit_log.write_tool_event("graph_find_relationship", result_summary=summarize_result(result))
    return result.to_dict()
```

```python
    limit: int = Field(default=10, ge=1, le=20)

@tool("graph_find_paths", args_schema=GraphFindPathsArgs)
def graph_find_paths_tool(
    workspace_id: str,
    knowledge_base_id: str,
    source_entity: str,
    target_entity: str,
    max_depth: int = 2,
    relationship_allowlist: list[str] | None = None,
    limit: int = 10,
) -> dict:
    """查询两个实体之间的受限多跳路径。P0 最大深度固定为 2。"""
    graph_query, _, audit_log = get_graph_services()
    assert_scope(workspace_id, knowledge_base_id)
    safe_depth = clamp(max_depth, 1, 2)
    safe_limit = clamp(limit, 1, 20)
    source = resolve_entity_or_disambiguate(source_entity, workspace_id, knowledge_base_id)
    target = resolve_entity_or_disambiguate(target_entity, workspace_id, knowledge_base_id)
    rels = filter_allowed_relationships(relationship_allowlist or [])

    paths = graph_query.find_paths(
        workspace_id,
        knowledge_base_id,
        source.entity_id,
        target.entity_id,
        safe_depth,
        rels,
        limit=safe_limit * 3,
    )
    paths = [preserve_direction(path) for path in paths]
    paths = rank_and_drop_search_only_paths(paths)
    result = ToolResult.ok({"paths": paths[:safe_limit], "empty": len(paths) == 0})
    audit_log.write_tool_event("graph_find_paths", result_summary=summarize_result(result))
    return result.to_dict()
```

- Neo4j TransientError 可重试。
- 普通模型不接触 Cypher，因此不存在让模型修复自由 Cypher 的流程。
- 管理员调试 Cypher 语法错误不可自动重试，只返回安全错误摘要。

### database_health_check LangChain Tool

`database_health_check` 给模型和诊断流程读取脱敏健康状态。它不能返回连接串、access key、password、token，只能返回可解释的健康摘要。实际连接测试由 Connector 内部通过 SecretResolver 读取 `access_key_ref`、`secret_key_ref`、`token_ref`、`credential_ref` 或 Redis `credential_ref` 后执行。Redis 只作为可重建缓存健康目标，不暴露给模型做业务读写。

LangChain Tool 伪代码：

```python
class DatabaseHealthCheckArgs(DatabaseScopeArgs):
    targets: list[str] = Field(default_factory=lambda: ["minio", "milvus", "neo4j", "redis"])
    refresh: bool = False

@tool("database_health_check", args_schema=DatabaseHealthCheckArgs)
def database_health_check_tool(
    workspace_id: str,
    knowledge_base_id: str | None = None,
    targets: list[str] | None = None,
    refresh: bool = False,
) -> dict:
    """读取 MinIO / Milvus / Neo4j / Redis 脱敏健康状态，供模型解释检索失败或配置问题。"""
    assert_user_can_read_workspace(current_user.id, workspace_id)
    safe_targets = filter_allowed_database_targets(targets or ["minio", "milvus", "neo4j", "redis"])
    result_by_target = {}
    for target in safe_targets:
        cached = health_cache.get(workspace_id, target)
        if cached and not refresh:
            result_by_target[target] = cached.public_dict()
            continue
        try:
            status = connector_factory.create(
                target=target,
                workspace_id=workspace_id,
                secret_resolver=secret_resolver,
            ).health_check(timeout=3)
            health_cache.write(workspace_id, target, status, ttl=30)
            result_by_target[target] = status.public_dict()
        except Exception as exc:
            result_by_target[target] = classify_database_error(exc).public_dict()

    result = ToolResult.ok({"targets": result_by_target})
    return finish_database_tool("database_health_check", result, {"targets": safe_targets, "refresh": refresh})
```

```python
def database_health_check_job(job: JobContext):
    targets = job.input.get("targets") or ["minio", "milvus", "neo4j", "redis"]
    timeout = job.input.get("timeout_seconds", 5)
    result = {}

    job.emit("stage_started", {"stage": "database_health_check", "targets": targets})

        try:
            status = connector_factory.create(
                target=target,
                workspace_id=job.workspace_id,
                secret_resolver=secret_resolver,
            ).health_check(timeout=timeout)
            result[target] = redact_database_health(status)
            job.emit("database_target_checked", {"target": target, "ok": status.ok})
        except Exception as exc:
            result[target] = classify_database_error(exc)
            job.emit("database_target_failed", {"target": target, "error": redact(exc)})

    snapshot = {
        "workspace_id": job.workspace_id,
        "checked_at": now_iso(),
        "source_job_id": job.job_id,
        "targets": result,
    }

    minio.write_json(database_health_latest_key(job.workspace_id), snapshot)
    minio.append_jsonl(database_health_history_key(job.workspace_id, now_date()), snapshot)
    job.write_leaf_state({"health": snapshot})
    job.emit("stage_completed", {"stage": "database_health_check", "progress_percent": 100})
```

## 跨数据库失败降级

| 失败点 | 降级 |
| --- | --- |
| Embedding API 失败 | 无法执行向量检索，询问用户或切备用 embedding 配置 |
| Milvus 检索失败 | 尝试 Neo4j 精确实体扩展，答案标明缺少向量召回 |
| Milvus 空结果 | 尝试 Neo4j 或要求用户换关键词 |
| MinIO 回源失败 | 只返回 metadata 不足以回答时应说明证据不可用 |
| Neo4j 查询失败 | 使用 Milvus 文本证据回答 |
| Neo4j 空结果 | 使用文本证据回答并说明未找到路径 |
| Rerank 失败 | 跳过 rerank，使用原始排序 |
