# 冲突与决策记录

## 已确认设计

- 不设置独立转发层，由 Agent Server / Runtime 承担入口和编排职责。
- 后端 Agent 编排使用 Python + LangChain + LangGraph。
- 数据层限定为 MinIO + Milvus + Neo4j。
- Milvus 做主向量检索，Neo4j 做实体关系和多跳扩展，MinIO 做原始文件和产物存储。
- 第一版网络优先使用 HTTPS REST + HTTPS SSE，本地 MCP 用 stdio，远程 MCP 用 Streamable HTTP。
- Tool 是能力，MCP 是外部工具协议，Skill 是提示词 / 流程 / 知识包 / 脚本包，SubAgent 是角色化执行单元。
- Redis 只作为可重建缓存，不作为锁、队列或主状态存储。
- 第一版使用 MinIO JSON / JSONL 作为主状态和产物存储，并增加轻量索引文件支持前端列表查询。
- 当前设计不使用 WebSocket；前端流式展示使用 SSE，控制动作使用 REST。
- P0 Skill Script 默认只读；允许写文件，但必须声明 `file_write` 范围，并走 Hook / 审批。
- 写入型 Skill Script 不直接改真实 workspace，必须先在沙盒 overlay 中生成 staged patch，审批通过后由 Runtime 受控提交。
- P0 支持受控并发 SubAgent，写入型任务必须分配互不重叠的写入范围，所有结果回到主 Agent 汇总审核。
- MCP 配置页面进入 P0，P0 支持只读查看和单个 MCP tool 启用 / 禁用。
- 模型可以直接看见所有已启用的普通 Tool、MCP Tool 和 SubAgent Tool；Skill 是例外，必须使用渐进式披露。
- MCP Tool 的模型可见命名统一为 `mcp_{server_name}_{tool_name}`。
- SubAgent 调用工具统一命名为 `call_subagent_{agent_type}`，不使用 Handoff 作为模型可见名称。
- `tool_inventory_snapshot` 是审计、调试、恢复快照，保存在 MinIO，不默认给大模型看。
- 用户名字、爱好、偏好进入 `user_profile` / `user_preference`，前端可见可改删，不需要审批，并会进入后续模型调用的 memory snapshot。
- 上下文压缩直接采用 Hermes 默认在线压缩机制，默认 50% 触发，85% 作为二级保护。
- 所有 LLM 类模型默认上下文窗口为 200000 tokens，默认最大输出为 8192 tokens，用户可以在 API 配置页面修改。
- API 配置页面、数据库配置页面、日志审计页面都进入 P0。
- P0 一个知识库只允许一个 active embedding 版本；更换 embedding 模型就新建 collection 并重新入库。
- 不引入额外 Catalog 数据库；Catalog 职责由 MinIO JSON / JSONL 和轻量索引文件承担。
- 不使用 pgsql、PostgreSQL、MySQL 保存 session/event/document/chunk 索引关系；这类索引关系由 MinIO 显式索引对象承担。
- 普通大模型只能通过参数化只读工具查询知识图谱，不能写 Neo4j，不能自由执行 Cypher。
- 重要技术细节必须在正式文档中写请求/返回结构、流程或伪代码，避免开发时回头猜设计意图。
- 模型工具伪代码优先使用 LangChain `@tool` / `StructuredTool` / Pydantic args schema；Agent 编排伪代码优先使用 LangGraph `StateGraph`、节点和条件边。
- 上下文压缩采用 Hermes 默认在线压缩策略：工具结果先压缩，保留 head 和 tail，中间历史生成结构化 summary。
- 图谱数据模型增强为 Document / DocumentVersion / Chunk / Mention / Entity / RelationFact / Evidence，保留 provenance。
- `knowledge_base_id` 是最终统一命名；`dataset_id` 只作为外部参考术语，不进入最终字段命名。
- P0 支持多对话窗口；`thread_id` 是一个前端可见对话，旧对话默认保留，不因为新建对话而删除。
- 前端主栈确认使用 React + TypeScript + Next.js + pnpm + `@lobehub/ui` + Antd + `antd-style`。
- 前端使用 `@lobehub/ui` 的视觉系统和基础组件，不 fork `lobehub/lobehub` 完整产品，不要求后端适配 LobeHub 原始接口。
- 前端 SSE 客户端确认使用 `fetch + ReadableStream`，不使用 `EventSource`。
- GraphRAG 前端 P0 采用路径列表和证据卡片展示，不做完整节点关系画布。
- P0 模型 Provider 范围为 OpenAI-compatible、Anthropic。
- Gemini、OpenRouter、本地模型、Ollama、LM Studio 放到 P1。
- context overflow 采用 Hermes 压缩并最多重试一次；仍失败时返回用户可见错误。
- P0 按单用户系统开发，不做登录页，但所有数据结构保留 `user_id` 和 `role`。
- P0 支持 workspace 概念，但默认只有一个 `workspace_id=default`，前端不做复杂 workspace 切换。
- `workspace` 是项目空间，不是对话窗口；对话窗口统一叫 `thread`。
- 所有数据路径、API、Tool 参数、日志和审计记录都保留 `workspace_id`。
- `user_profile` 是全局记忆。
- `user_preference` 支持 `global` 和 `workspace` 两种 scope。
- `project_fact` / `project_rule` 是 workspace 级记忆。

## 已解决：用户、Workspace 和权限模型

当前决策：

```text
P0 单用户，无登录页。
默认 user_id = default_user。
默认 role = owner。
默认 workspace_id = default。
默认 workspace_role = owner。
```

落地规则：

- `workspace` 表示项目空间，不是对话窗口。
- `thread` 表示 workspace 内的一个前端可见对话窗口。
- P0 默认只有一个 workspace，前端不做复杂 workspace 切换。
- 后端 `/bootstrap` 返回默认 user、role、workspace 和 feature flags。
- 所有 workspace 级 API 必须带 `workspace_id`。
- 所有 LangChain Tool 参数、LangGraph AgentState、MinIO object key、Milvus metadata、Neo4j scope、日志和审计事件必须保留 `workspace_id`。
- P0 只启用 `owner` 角色，但保留 `owner`、`admin`、`editor`、`viewer` 枚举。
- P0 代码仍必须调用 `assert_current_user`、`assert_user_can_read_workspace`、`assert_user_can_manage_workspace` 等 scope guard。
- `user_profile` 永远是 global scope，用于用户名字、称呼等用户级资料。
- `user_preference` 支持 global 和 workspace scope；全局输出风格属于 global，项目特殊偏好属于 workspace。
- `project_fact` / `project_rule` 永远属于 workspace scope。
- 新建 thread 不继承旧 thread 的短期上下文，但会注入启用状态的 global memory 和当前 workspace memory。

## 已解决：Provider 兼容层和 context overflow

- Runtime 不直接依赖供应商原始响应格式，所有模型调用先进入 Provider Adapter。
- P0 Provider：`openai_compatible`、`anthropic`。
- P1 Provider：`gemini`、`openrouter`、`ollama`、`lm_studio`、`local_openai_compatible`。
- 模型配置必须保存 `context_window_tokens` 和 `max_output_tokens`；API usage 只记录本次消耗，不作为模型最大上下文窗口来源。
- LLM 默认 `context_window_tokens=200000`，`max_output_tokens=8192`，用户可在 API 配置页修改。
- Provider Adapter 输出统一 `ModelRequest`、`ModelStreamEvent`、`ModelResult`、`ModelUsage`、`ModelError`、`ToolCallDelta`。
- 模型能力字段必须入配置：streaming、tool_calling、parallel_tool_calls、vision、json_mode、prompt_cache。
- context overflow 来源包括调用前本地预算超限，以及 provider 返回 context length exceeded / token limit exceeded。
- context overflow 流程：Hermes 压缩、裁剪可回源证据、重算预算、最多重试 1 次模型调用。
- 重试后仍然 overflow 时，写 `model_call_failed` 事件，并向用户显示可见错误。
- Provider 错误统一分类：`rate_limit`、`provider_5xx`、`timeout`、`connection_lost`、`stream_ended_before_terminal`、`context_overflow`、`auth_failed`、`model_not_found`、`billing_required`、`quota_exceeded`、`invalid_request`、`content_filter`、`unsupported_feature`。
- 流式 tool call delta 必须在 Adapter 内组装完整 JSON arguments 后再交给 Tool Executor；orphan tool call 必须生成错误 ToolResult，不能破坏 replay。

## 已解决：多对话窗口和历史会话保留

- `thread_id` 表示一个前端可见对话窗口。
- `run_id` 表示 thread 中一次用户提交后的 Agent 执行。
- `message_id` 表示 thread 消息流中的一条持久化消息。
- `event_id` 表示 run 内部事件，用于 SSE 补发、工具状态和审计。
- 新建 thread 不删除旧 thread。
- 旧 thread 默认保留在 MinIO 的 `sessions/{thread_id}` 路径下。
- 左侧历史列表由 `workspaces/{workspace_id}/indexes/threads_index.json` 支撑。
- 单个 thread 的消息由 `sessions/{thread_id}/messages/part-*.jsonl` 和 `message_index.json` 支撑。
- 单个 thread 的运行列表由 `sessions/{thread_id}/runs_index.json` 支撑。
- 删除对话默认软删除，设置 `status=soft_deleted` 并从默认列表隐藏，不物理删除消息、run、事件和审计日志。
- 归档对话只从默认 active 列表隐藏，归档筛选仍可查看。
- 新 thread 不继承旧 thread 的短期上下文和 compaction。
- 长期记忆 `user_profile` / `user_preference` 可以跨 thread 注入，受 `enabled_for_model_context` 控制。
- 旧会话历史检索使用 `session_search` 和 `session_message_get`，不等同于长期记忆。

## 已解决：MinIO JSON 作为第一版主状态

第一版确认把 `manifest.json`、`chunks.json`、`events/part-*.jsonl`、`operations.jsonl` 作为核心状态文件，同时增加轻量索引文件：

- `workspace_index.json`：工作区索引入口。
- `documents_index.json`：文档列表摘要。
- `runs_index.json`：运行任务列表摘要。
- `memory_index.json`：长期记忆列表摘要。
- `runs/{run_id}/manifest.json`：单次 Agent run 权威状态。
- `runs/{run_id}/events/part-*.jsonl`：单次运行分段事件日志。
- `runs/{run_id}/event_index.json`：run 事件分页、SSE 断线补偿和重放索引。
- `runs/{run_id}/leaf_state.json`：run 当前可恢复快照。

决策原则：

- MinIO 保存主状态、原始文件、可回源产物和日志。
- 轻量索引用于列表查询，不保存完整正文和完整事件。
- 轻量索引可以从权威 JSON / JSONL 重建。
- 不引入额外元数据库。
- 原本可能由 pgsql 承担的 session/event/document/chunk 索引关系，改为 MinIO manifest、index、JSONL 和 snapshot 对象。
- Redis 只缓存热索引，不作为权威状态，不做锁，不做队列。
- Milvus 继续只负责向量检索。
- Neo4j 继续只负责实体关系和多跳扩展。

落地规则：

- 每个 run 同一时间只能有一个 EventStoreWriter。
- EventStoreWriter 负责为事件分配递增 `event_seq` 和幂等 `event_id`。
- 事件 ID 规则为 `evt_{run_id}_{event_seq_12位补零}`。
- 事件先写入 `events/part-*.jsonl`，再更新 `event_index.json` 和 `leaf_state.json`。
- `event_index.json` 支持 `after_event_id` 分页和 SSE 断线补偿。
- `leaf_state.json` 保存 pending approval、active tool calls、active subagents、last_compaction_id、memory_snapshot_id、tool_inventory_hash 等恢复字段。
- 所有可重写索引对象必须有 `revision`，写入时使用 etag / revision 乐观并发控制。
- 多 Runtime 实例通过 `runs/{run_id}/manifest.json` 中的 `owner.fencing_token` 控制 run ownership。
- 索引损坏或缺失时，由 IndexRebuilder 从 manifest、events、operations、chunks、memory 原文重建。
- 高频 token 不逐 token 落 MinIO，按 250ms 或 512 字符聚合为 `assistant_delta`，最终写完整 `assistant_message`。

## 已解决：Neo4j 第一版范围

第一版确认：

```text
P0：基础自动图谱入库 + 只读 GraphRAG 查询。
```

P0 做：

- 文档入库 pipeline 支持 Document Representation、文档级 metadata、chunk 级抽取、实体归一化、关系标准化、关系合并。
- Neo4j schema 使用 Document / DocumentVersion / Chunk / Mention / Entity / RelationFact / Evidence。
- 查询时 Milvus 召回 chunk，Neo4j 做 1 到 2 跳扩展。
- 普通模型问答只使用只读 graph tool。

P0 不做：

- 图谱可视化编辑。
- 复杂关系权重系统。
- 人工审核后台。
- 自动图谱质量优化。
- 多知识库全局实体主数据治理。

外部接口边界：

- 普通 LLM 只能调用 `graph_schema_get`、`graph_entity_search`、`graph_expand_entity`、`graph_find_relationship`、`graph_find_paths`、`graph_get_evidence`、`graph_timeline_query`、`graphrag_search`。
- 普通 LLM 不允许调用 `graph_write_batch_internal`。
- 普通 LLM 不允许调用自由 `graph_readonly_query`。
- `graph_write_batch_internal` 只允许入库 pipeline、图谱重建任务、管理员维护任务调用。
- `graph_readonly_query_admin` 只允许管理员诊断页调用，必须只读账号、白名单、timeout 和 LIMIT。
- 所有图谱查询工具都必须带 `workspace_id` 和 `knowledge_base_id`。
- 所有图谱路径返回必须保留关系方向、关系类型、relation_strength、rank_penalty 和 evidence 引用。

## 已解决：关系方向和关系权重

P0 确认：

- P0 不做复杂关系权重配置系统。

后续可扩展：

- 文档类型级关系权重。
- 基于评估结果自动调整权重。

## 已解决：Redis P0 缓存范围

当前决策：

```text
Redis P0 只承担可重建缓存职责，不保存主状态，不做锁，不做队列。
```

P0 缓存：

- MCP tool list。
- capability snapshot。
- query embedding。
- 数据库连接健康状态。
- Milvus 检索结果。

P0 暂不缓存：

- Neo4j 图谱路径。
- rerank 结果。
- approval 状态。
- 工具执行进度。
- 最终回答内容。

Milvus 检索结果缓存规则：

- 缓存 key 必须包含 `workspace_id`、`knowledge_base_id`、collection、embedding model、知识库版本、query embedding hash、filters hash、top_k。
- 缓存 value 默认只保存 `chunk_id`、`doc_id`、`doc_version_id`、score，不保存 chunk 正文。
- 文档新增、删除、重切块、重新 embedding、collection 重建、embedding 模型变化、权限变化时必须失效。
- Redis 不可用、读取失败、写入失败时均不阻断主检索链路，直接回源查询 Milvus。

落地规则：

- Skill 是提示词、流程、知识包、操作经验和可选脚本的组合。
- Skill 脚本入口必须在 manifest 中声明。
- Skill 必须有版本号。
- Skill 必须声明依赖的 Tool、MCP、模型、数据库、网络和文件权限。
- 脚本入口必须声明 args schema、output schema、risk_level、sandbox_profile、timeout 和 checksum。
- 写文件型脚本入口必须声明 `write_mode: staged_patch`、`file_write`、`allow_create`、`allow_modify`、`allow_delete`。
- 模型不能直接执行 Skill 包里的脚本路径。
- Runtime 通过 Skill Runner 执行脚本，并套用参数校验、Hook、审批、沙盒、日志和 ToolResult。
- 写入型 Skill Script 在沙盒 overlay 中生成 staged patch，不直接修改真实 workspace。
- Runtime 收集 diff.patch、operation_plan、changed_files 和 diff_summary 后发起审批。
- 审批通过后，由 Runtime 的受控 FileSystemConnector / apply_patch 提交 diff，并记录 operation_id / rollback_token。
- 脚本执行记录必须绑定 `skill_id`、`skill_version`、`script_entry`、`script_checksum`、`args_hash`、`trace_id`。
- 每次脚本执行都保存到 `workspaces/{workspace_id}/runs/{run_id}/skill_runs/{skill_run_id}/...`。
- 修改脚本内容、参数 schema、输出 schema 或新增高风险权限时必须记录版本和变更摘要。
- 新增文件写、数据库写、网络、进程等高风险权限必须审批。
- P0 优先支持 Python 类脚本；Shell / 系统命令类脚本可以打包，但默认高风险，需要强审批和更严格沙盒。
- P0 不允许脚本运行时随意安装依赖；依赖必须在安装或更新 Skill 时构建并记录 environment hash。
- 脚本超时后 kill 沙盒进程树；同一 run 内同一 entrypoint 连续失败达到 3 次时临时禁用。

## 已解决：上下文压缩采用 Hermes 默认机制

当前决策：

```text
P0 直接采用 Hermes 默认在线压缩机制。
```

落地规则：

- 默认 engine 是 Hermes 风格 `ContextCompressor`。
- 默认 `compression.enabled = true`。
- 模型默认 `context_window_tokens = 200000`，默认 `max_output_tokens = 8192`，这两个值来自 API 配置页面。
- 默认 `compression.threshold = 0.50`，prompt tokens 达到模型上下文窗口 50% 时触发压缩。
- 默认 `compression.target_ratio = 0.20`，tail token 保护预算 = threshold_tokens * 0.20。
- 默认 `protect_last_n = 20`，至少保护最近 20 条消息。
- 默认 `protect_first_n = 3`，保护开头 3 条消息。
- session hygiene 在模型上下文窗口 85% 时触发二级保护。
- 不做中间 context pressure warning，避免模型因为上下文压力提示过早放弃复杂任务。
- 工具结果先做低成本裁剪，再做对话摘要压缩。
- protected tail 之外的旧工具结果如果过长，替换为短占位摘要。
- tool_call / tool_result 成对关系不能被拆坏。
- 压缩后结构是 `head 原文 + structured summary + tail 原文`。
- 压缩摘要保存到 MinIO，但不能成为唯一历史。
- 原始 transcript 和原始 tool result 必须落盘，并通过 message_id / tool_call_id 与摘要关联。
- 压缩摘要默认不自动提升为长期记忆；只有稳定事实被抽取成候选记忆后，才进入长期记忆流程。
- 第一次压缩生成结构化 summary；后续压缩用 previous_summary 增量更新。
- P0 不做完整 LCM / Summary DAG。

摘要预算：

```text
context_window_tokens = 200000
max_output_tokens = 8192
usable_input_budget = 191808
summary_tokens = content_tokens * 0.20
min_summary_tokens = 2000
max_summary_tokens = min(context_length * 0.05, 12000)
```
