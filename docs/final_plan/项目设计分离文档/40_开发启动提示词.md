更新时间：2026-05-30

## 给新对话窗口 AI 的提示词

把下面这段完整发给新的开发对话窗口：

```text
【当前任务】
你要开始开发一个 Agent 系统。所有前期设计资料已经整理在：

C:\Users\Administrator\Desktop\Agent design\前期技术栈设计\final_plan

真实代码项目必须创建在：

C:\Users\Administrator\Desktop\Agent design\前期技术栈设计\agent-system

不要在 final_plan 里写运行时代码。final_plan 只作为最终设计资料和开发日志资料。

【必须先读】
请先按顺序读取：

1. final_plan/项目设计分离文档/00_总览与设计原则.md
2. final_plan/项目设计分离文档/35_P0开发规划与验收矩阵.md
3. final_plan/项目设计分离文档/36_项目脚手架与目录结构设计.md
4. final_plan/项目设计分离文档/37_统一API契约索引.md
5. final_plan/项目设计分离文档/38_Pydantic数据模型与Schema设计.md
6. final_plan/项目设计分离文档/39_DockerCompose与环境变量设计.md
7. final_plan/_development_logs/master_plan.md

然后开始 Phase A：基础工程和本地环境。

【项目硬性边界】
- 后端：Python + FastAPI + LangChain + LangGraph。
- 前端：React + TypeScript + Next.js + pnpm + @lobehub/ui + Antd + antd-style + Zustand。
- 数据层：MinIO + Milvus + Neo4j。
- Redis 只做可重建缓存，不做锁、不做队列、不做主状态。
- 网络：REST + SSE，不使用 WebSocket。
- 不使用 Gateway。
- 不使用 PostgreSQL、MySQL、pgsql 或独立 Catalog DB。
- P0 模型 Provider 只做 OpenAI-compatible 和 Anthropic。
- P0 默认单用户：default_user / owner。
- P0 默认 workspace：default。

【测试模型】
当前可先用一个 OpenAI-compatible 测试模型跑通 Phase C 之前的调用链：

provider: openai_compatible
model: mimo-v2.5-pro
base_url: https://token-plan-cn.xiaomimimo.com/v1
api_key: <set in private .env or Secret Store>
api_key_ref: secret_mimo_openai_compatible_key

embedding_provider: openai_compatible
embedding_model: text-embedding-v4
embedding_base_url: https://dashscope.aliyuncs.com/compatible-mode/v1
embedding_api_key: <set in private .env or Secret Store>
embedding_api_key_ref: secret_dashscope_text_embedding_v4_key
embedding_dimension: 1024

测试 API key 不能提交到 GitHub；开发时放入私有 `.env` 或 Secret Store。实现时仍要支持 Secret Store，并分别创建 `secret_mimo_openai_compatible_key` 和 `secret_dashscope_text_embedding_v4_key` 作为正式配置引用；日志、诊断包、前端响应、Tool 参数回显、SubAgent 报告不能输出明文 key。

【Secret Store 简要理解】
Secret Store 是系统自己的加密密码库。用户输入 API key / 数据库密码后，后端用 AGENT_MASTER_KEY 加密，密文存 MinIO。业务配置只保存 secret_ref，运行时只有后端 SecretResolver 能解密使用。模型、前端、Tool、Skill、SubAgent、日志都不能看到明文。

【Phase A 目标】
创建 agent-system 项目，完成：

1. 后端 FastAPI skeleton。
2. 前端 Next.js skeleton。
3. deploy/compose/docker-compose.local.yml，包含 MinIO、Milvus、Neo4j、Redis。
4. .env.example。
5. /bootstrap，返回 default_user / owner / workspace_id=default。
6. 基础健康检查。
7. final_plan/_development_logs 下创建 devtask_phase_a_foundation 的任务、事件和验证记录。

【SubAgent 使用规则】
如果你调用 Codex SubAgent：
- 先声明 read_scope 和 write_scope。
- 不允许两个 SubAgent 并发写同一文件、目录、配置 namespace 或前端 store。
- SubAgent 只提交报告，最终修改和验收由主 Agent 汇总。
- 参考 final_plan/项目设计分离文档/35_P0开发规划与验收矩阵.md 的 SubAgent 分工。

【Phase A 推荐 SubAgent】
- agent-organizer：拆 Phase A 子任务。
- docker-expert：写 docker compose。
- fastapi-developer：写后端 skeleton 和 /bootstrap。
- frontend-developer：写前端 skeleton。
- typescript-pro：检查前端类型。
- qa-expert / test-automator：写基础验收测试。

【验收标准】
Phase A 完成时至少满足：

- agent-system 目录结构符合 36_项目脚手架与目录结构设计.md。
- docker compose 能启动 MinIO、Milvus、Neo4j、Redis。
- 后端 /bootstrap 可返回默认身份和 workspace。
- 前端能读取 /bootstrap 并显示基础工作台入口。
- 有 .env.example。
- 有开发日志和验证记录。
- 未完成或未测试项必须明确写出原因。

请先做 Phase A，不要跳到 RAG、MCP、Skill 或 SubAgent。
```

## 给用户的提醒

- 当前 OpenAI-compatible 测试 key 已写入最终设计文档，开发 AI 可以先用它跑通 P0 本地链路。
- 正式部署或多人协作前，把明文 key 迁移到 Secret Store 或本地私有环境变量。
- 第一轮开发只做 Phase A，不要贪多。
- Phase A 完成后再让开发 AI 进入 Phase B。
